An Icon Button is a button in the interface that uses a specific icon to represent a function, and is typically intuitive to use and saves space. When the operation is familiar to users and is associated with an icon, consider using an icon button.

## Anatomy
### Content
The button is designed with a circular shape. It is available in two distinct forms. The first features a background, which adds color and depth to the button, making it stand out on the page and attract the user's attention. The second is a form without a background, where the pure icon button appears more simple and minimalistic, allowing it to blend seamlessly with various interface styles and providing users with a clean and refreshing user experience.
![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/a322fa00d20341f7b53a6b9be0e4bfe9~tplv-goo7wpa0wc-image.image)
### Dimensions
Available in four sizes—Min, Small, Regular, and Max—you can select the appropriate size according to different scenarios and business requirements.
![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/e309428660bd482190e05edec201e4dc~tplv-goo7wpa0wc-image.image)
### Role
There are 4 types of Icon Button:

* Primary button: Uses a dark background with a light icon. This is the default button state and is typically the button users are most likely to select.
* Secondary button: Uses a light background with a dark icon and is suitable for scenarios where there is no distinction between primary and secondary buttons.
* Other buttons feature a light background paired with light icons, a blurred background effect, and are commonly used over images or text.
* Button without background: In a non-interactive state, only the button is visible without any background. This typically occurs when buttons of the same size are used to provide two or more options, indicating that these options form a coherent group of choices.

## Interactive behavior
Buttons are divided into four interaction states:

* normal state: The button's default display state when no actions are performed and no special circumstances occur.
* hover state: When a hand pose or other method passes over the button, the background color changes. This state can also serve as a predictive operation and provide immediate UI feedback, reassuring users that they can confidently press or interact with the button.
* Pressed state: When the button is pressed, a click event is triggered and the button's background color changes. This state provides immediate UI feedback to inform the user that they have interacted with the button element.
* Disabled state: Due to certain reasons, the button is currently not operable by the user and is displayed as grayed out.

![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/4628fb3b2a474761a6d76a8ec83ce4d1~tplv-goo7wpa0wc-image.image)
Activated button state: refers to the specific form a button displays after being selected by the user through a particular action. This approach is intended to clearly convey to users that the button is currently activated, selected, or functioning, with a change in the button's background color.
