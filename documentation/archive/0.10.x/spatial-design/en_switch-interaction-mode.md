During the process of system interaction, users can set their preferred interaction modes, and the system manages the ongoing interaction modes based on the user's behavioral intent. During the development of spatial applications, developers should also pay attention to the appropriate management of the various interaction methods provided by the system.

* User settings
   In the system's interaction settings, users can configure how to switch the default interaction mode. When designing applications, developers should fully consider supporting various interaction modes.
* Automatic switching mechanism
   Based on the user's customized interaction settings, the usage status of external devices, and the user's real-time interaction intent, PICO OS 6 automatically switches between interaction modes. For example, when the user's hand approaches an interactive object, the primary interaction mode will switch from eye-hand interaction (gaze and pinch) to direct gesture interaction. Similarly, when the user connects and uses external devices such as an XR controller or mouse, the system will automatically switch to the corresponding controller ray, mouse, and other interaction modes. For more details, see "[Motion-based interaction](/en_motion-based-interaction)."
* Application constraints on interaction methods
   Application developers can restrict how objects within the application respond to interactions according to design requirements, in order to achieve the goal of making the application more intuitive and easy to use.
   For example, when you want to interact with a virtual pottery jar, you hope to use the index finger and thumb pinch gesture to drag the jar, and use the index finger poke gesture to paint on its surface. To distinguish between these two interaction methods, you can access the source type of the interaction method from the generic event to differentiate the operations and achieve the desired effect. For more information, see "[Motion-based interaction](/en_motion-based-interaction)".
* System-level interaction commands
   In some cases, system behavior restricts specific interaction methods from performing special operations, such as system gestures and headset buttons, which would otherwise be used to trigger the system interface, adjust the volume, and adjust the immersion level. These system-level interaction commands play a critical role in supporting stable system operation and have a higher priority. Therefore, developers should avoid these operations during the design process to prevent conflicts. For more information, see "[System commands - system hand poses](/en_hand-poses-as-system-commands)" and "[System commands - HMD buttons](/en_hmd-buttons-as-system-commands)".
