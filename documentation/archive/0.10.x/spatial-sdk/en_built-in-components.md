PICO Spatial SDK provides a set of feature-rich built-in components that support common needs in 3D scenes, including modeling, interaction, rendering, physics, environmental awareness, audio and video, and more. These components encapsulate basic capabilities in a modular form. You only need to add the corresponding components to an entity to quickly assign specific properties or behaviors to objects, enabling you to efficiently build your spatial apps.
## Transform component
The `TransformComponent` is used to adjust the transform of an entity, including position, rotation (supports representation using EulerAngles with pitch, yaw, and roll, or Quat), and scale.
## Model component
The `ModelComponent` consists of meshes and materials, and is used to bind a model to an entity. You can programmatically create meshes and materials, and use them as parameters to generate a `ModelEntity` instance, which automatically includes `ModelComponent`. If an entity is created by loading a USD or glTF model file, or by using `bundle.loadModel`, the `ModelComponent` will also be added automatically. For further information about resources such as mesh, texture, and material used for creating 3D models, refer to "[Model](/en_model)".
## Interaction-related component
To make an entity interactable, you need to add `InteractableComponent` and `CollisionComponent` to it. Among them, the `CollisionComponent` is used to define the shape and range of collision detection for interactions. For more information on spatial interaction, refer to "[Spatial interaction](/en_spatial-interactions)".
## Rendering-related component
To enhance the scene's rendering effect, you can add image-based lighting components to the scene, such as `ImageBasedLightComponent` or `StageEnvironmentLightingComponent`. These components bake lighting effects into the map, enabling the simulation of lighting effects for specific scenarios with lower performance cost. However, this method cannot generate shadows.
If you need to add shadows in a scene, you can use the `GroundingShadowComponent`. It can dynamically simulate the shadow effect when the light source is directly above the object. However, the shadow effect it produces is always below the object and cannot simulate changes in shadow when the light source is in other positions.
If you want to achieve both dynamic lighting and shadow effects, you can use dynamic light components, such as `DirectionalLightComponent`, `PointLightComponent`, and `SpotLightComponent`. Note that dynamic lighting and shadowing increase performance overhead, so it is necessary to balance visual effects and performance.
For more information on lighting and shadowing, refer to "[Image-based lighting](/en_image-based-lighting)", "[Dynamic lighting](/en_dynamic-lighting)", and "[Dynamic shadowing](/en_dynamic-shadowing)". For performance-related content, refer to the "[Performance & debugging](/en_spatial-app-performance-overview)" chapter.
## Physics-related component
When an app needs to support physical effects such as rigid bodies, collisions, external forces, and more, you can use components like `RigidBodyComponent, CollisionComponent`, `PhysicsForceComponent`, and `PhysicsVelocityComponent`. You can also manage the local physics world through `PhysicsWorldComponent`. For more information on physics simulation, refer to the "[Physics](/en_physics-simulation)" chapter.
## Environmental perception-related component
If you want to bind an entity to an anchor in the real world, you can use `AnchorComponent`. It can anchor an entity at a specific position in the real world, or bind it to markers such as a camera, plane, or mesh, and ensure that the entity maintains a constant relative position to these markers. When the anchor changes, the entity will automatically update based on the anchor's position and orientation. For more information about anchors, refer to "[Spatial anchor](/en_spatial-anchor)".
## Audio-related component
To achieve rich and immersive spatial audio effects, you can use `ChannelAudioComponent`, `AmbientAudioComponent`, or `ObjectAudioComponent`. In addition, `AudioResourceLibraryComponent` can be used to manage the audio resource dictionary, and `AudioMixGroupsComponent` can be used to manage audio reverb groups. For more information, refer to the "[Audio](/en_spatial-audio-overview)" chapter.
## Video-related component
Spatial video playback can be implemented using `VideoComponent` and `VideoPlayerComponent`. `VideoComponent` provides flexible buffer control, allowing you to manage video playback with a custom player. `VideoPlayerComponent` offers a simpler interface that encapsulates player operations, enabling you to play videos directly without the need for decoding. For more information, refer to the "[Video](/en_video-types)" chapter.
