ShaderGraphMaterial created by the visual material editor in the Spatial Editor. When used in the SDK, it operates as a material instance within spatial apps, and holds and saves all adjustable parameters and resource binding information exposed by the shader.
## Use cases
The key use cases of ShaderGraphMaterial in spatial apps are as follows:

* **Dynamic material effects**
   Use time, noise, or UV offset animation to create dynamic visual effects on the surface, such as water ripples, flames, halos, dissolving, and sweeping light.
* **Complex texture processing**
   Mixing multiple maps within a material or using vertex colors or mask partitioning to implement ground layering, multi-skinned characters, and channel packing to reduce the number of samplings.
* **Lighting and shadow control**
   Customize or adjust lighting response, for example, toon segmentation, highlight enhancement, or simple subsurface scattering or translucency, to achieve stylized or special shadow effects.
* **Transparency and special effect surfaces**
   Change glow, color flicker, and dissolve threshold to indicate the state of hit or skill charging.
* **Visual debugging**
   Quickly display normals, UVs, depth gradients, and mask areas to assist with troubleshooting.

## Important notes
When using ShaderGraphMaterial in the PICO Spatial SDK, pay attention to the following:

* The parameter names and types of ShaderGraphMaterial must be consistent with your configuration in Spatial Editor; otherwise, an exception will be thrown.
* Use `Matrix` type parameters with caution to avoid potential compatibility or performance issues.

## Load ShaderGraphMaterial
### Retrieve the configured ShaderGraphMaterial through a scene
Currently, ShaderGraphMaterial can only exist in the AssetBundle generated by the Spatial Editor. If you configure a ShaderGraphMaterial for an entity in a Scene within the Spatial Editor, then when the scene is loaded through an AssetBundle, the `ShaderGraphMaterial` instance will be loaded together with the entity.
```Kotlin
val bundle = AssetBundle.load("asset://XXX.bundle")
val model = bundle.loadModel("Hi")
// The AA entity has a ModelComponent and is assigned a ShaderGraphMaterial instance in the Spatial Editor
val AA = model.findEntity("AA")!!
val modelComp = AA.components[ModelComponent::class.java]!!
val  material = modelComponent.materials[0]
material is ShaderGraphMaterial
```

### Load a new ShaderGraphMaterial instance through AssetBundle
In addition to the ShaderGraphMaterial bound to the scene, you can also load a ShaderGraphMaterial separately from an AssetBundle by specifying a path and use it to create a new entity. The path is related to the scene, for example:

* `"SceneName/Root/Material"`
* `"SubFolder/SceneName/Root/Material"` (There is a subdirectory named /SubFolder under the /Scenes directory)
* `"SubFolder/SubSubFolder/SceneName/Root/Material"` (There is a subdirectory named /SubFolder/SubSubFolder under the /Scenes directory)

![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/112cfb90bf7b499cb07992fa02225c98~tplv-goo7wpa0wc-image.image)
As shown in the figure above, "shaderGraphMaterial" is a ShaderGraphMaterial that has already been created, and its loading path is `"Hi/Root/MyMaterials/shaderGraphMaterial"`. In code, you can use the static method provided by the `ShaderGraphMaterial` class to load this material and use it to create a new entity.
```Kotlin
val bundle = AssetBundle.load("asset://XXX.bundle") // xxx is the AssetBundle name configured by you
val shaderGraph = ShaderGraphMaterial.loadFromAssetBundle(bundle, "Hi/Root/MyMaterials/shaderGraphMaterial")
val mesh = MeshResource.createSphere(0.2f)
val shaderGraphEntity = ModelEntity(mesh, shaderGraph)
```

## Set or get the properties for ShaderGraphMaterial

* Get the name:
   ```Kotlin
   // The name should be the one set in the Spatial Editor
   val name = shaderGraph.getName() // name is "shaderGraphMaterial"
   ```

* Set or get  the `BlendingMode`:
   ```Kotlin
   shaderGraph.setBlendingMode(BlendingMode.ADD)
   val blendingMode = shaderGraph.getBlendingMode()
   ```

* Set or get the `CullingMode`:
   ```Kotlin
   shaderGraph.setCullingMode(MaterialCullingMode.FRONT)
   val cullingMode = shaderGraph.getCullingMode()
   ```

* Set or get the `PolygonFillMode`:
   ```Kotlin
   shaderGraph.setPolygonFillMode(PolygonFillMode.LINE)
   val polygonFillMode = shaderGraph.getPolygonFillMode()
   ```

* Set `DepthTest` or get the state of `DepthTest`:
   ```Kotlin
   shaderGraph.setDepthTest(false)
   shaderGraph.getDepthTest()
   ```

* Set `DepthWrite` or get the state of `DepthWrite`:
   ```Kotlin
   shaderGraph.setDepthWrite(false)
   shaderGraph.getDepthWrite()
   ```


## Manage custom parameters for ShaderGraphMaterial
In Spatial Editor, you can view the supported types of input node in the Shader Graph. ShaderGraphMaterial supports 11 types of custom parameters. The input node you define is a custom parameter that can be adjusted at runtime.
![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/ec30d2e9be6c4232adc9930ef56e7cb7~tplv-goo7wpa0wc-image.image)
The figure above shows the 11 parameter types supported by input node, which correspond to the parameter types in the PICO Spatial SDK as follows:
| **Input node types in Spatial Editor** | **Corresponding parameter types of PICO Spatial SDK** |
| --- | --- |
| Integer | Int |
| Boolean | Boolean |
| Float | Float |
| Color3 | Color3 |
| Color4 | Color4 |
| Vector2 | Vector2 |
| Vector3 | Vector3 |
| Vector4 | Vector4 |
| Matrix3 | Matrix3 |
| Matrix4 | Matrix4 |
| Filename | TextureResource |
You can set or get parameters through overloaded interfaces or generic interfaces. Parameter names must be consistent with those configured in Spatial Editor, and their types must also match.

* Get all parameter names:
   ```Kotlin
   val names = shaderGraph.getParameterNames()
   ```

* Set the value of a parameter by its name:
   ```Kotlin
   // The type is Int
   shaderGraph.setParameter("param_name", 10)
   
   // The type is Boolean
   shaderGraph.setParameter("param_name", false)
   
   // The type is Vector3
   shaderGraph.setParameter("param_name", Vector3(10f, 10f, 10f))
   
   // The type is TextureResource
   val texture = TextureResource("name.png")
   shaderGraph.setParameter("param_name", texture)
   ```

* Get the value of a parameter by its name:
   ```Kotlin
   // The type is Int.
   val intValue = shaderGraph.getParameter<Int>("param_name")
   // The type is Boolean
   val boolValue : Boolean = shaderGraph.getParameter("param_name")
   // The type is Vector3
   val vector3Value = shaderGraph.getParameter("param_name", Vector3::class.java)
   // The type is TextureResource
   val textureValue = shaderGraph.getParameter<TextureResource>("param_name")
   ```


## Use a ShaderGraphMaterial on multiple models
Currently, ShaderGraphMaterial does not support deep copy. If you need to apply the same ShaderGraphMaterial to multiple models but implement different effects, each model must load a separate `ShaderGraphMaterial` instance.
```Kotlin
val shaderGraphMaterialA =
 ShaderGraphMaterial.loadFromAssetBundle(bundle, "XXXXXX/Material")
val shaderGraphMaterialB =
 ShaderGraphMaterial.loadFromAssetBundle(bundle, "XXXXXX/Material")
val shaderGraphMaterialC =
 ShaderGraphMaterial.loadFromAssetBundle(bundle, "XXXXXX/Material")
val mesh = MeshResource.createSphere(0.2f)
val shaderGraphEntityA = ModelEntity(mesh, shaderGraphMaterialA)
val shaderGraphEntityB = ModelEntity(mesh, shaderGraphMaterialB)
val shaderGraphEntityC = ModelEntity(mesh, shaderGraphMaterialC)
```

## Create a ShaderGraphMaterial in Spatial Editor
In the Shader Graph panel of Spatial Editor, you can create materials and adjust their parameters by dragging and connecting nodes, without manually writing shader code such as HLSL or GLSL. For more information, refer to [Shader Graph basic operations](/document/spatial-toolkit/1xg7gkyf/) and [Shader Graph node descriptions](/document/spatial-toolkit/pp5b2o6p/).
